# Migrate 0.2 to Haskell 0.3

The `0.3` path is a change of runtime ownership, not an in-place upgrade of the
`0.2` daemon stack. Clef workflows become ordinary Haskell programs, and
Tactus becomes a small project-local CLI. There is no automatic translator for
Python workflow builders, script cells, checkpoints, artifact state, or Segno
schedules.

Keep the old checkout, environment, and state intact until the new Haskell
programs pass their own checks. Do not point a `0.3` workspace at `0.2` daemon
state or assume mixed-version compatibility.

## What changes

| `0.2` surface | `0.3` destination |
| --- | --- |
| Python Clef builders and RPC facade | Haskell `Task input output`, `Operation output`, and `Workflow a` |
| Rust daemon scheduler and global workflow graph | Ordinary Haskell control flow; explicit `parallel` is the Clef concurrency primitive |
| Tactus Python cells and optional Jupyter worker | Numbered `.hs`/`.lhs` entry programs plus normal Haskell helper modules |
| Provider-specific in-process assumptions | One-shot `agenstro.plugin/v1` JSONL subprocess adapters |
| Checkpoint, CAS, artifact, or rollback behavior | Segno has explicit typed business-state checkpoints/CAS only; no artifact, workspace transaction, or rollback replacement |
| Motivo daemon/editor/terminal | Thin TypeScript/React visualization over the Rust Tactus control API; no daemon, terminal, or direct state parsing |
| Python/Rust Segno scheduling/replay | Re-author as a Haskell `PersistentTask`; initialize fresh `.tactus/segno` state; no old registry/database importer and no replay claim |

The removed Python surfaces, Clef/Tactus Rust product cores, and shared
Protobuf/foundation crates are available only through Git history, including
snapshots `3eef756` and `c679f45`. None of those historical implementations
define `0.3` support.

## 1. Establish the new toolchain

Use Rust 1.88 or newer and a GHC whose bundled `base` satisfies
`>=4.20 && <4.23`. From the Agenstro repository root:

```powershell
cabal build --builddir=Build/cabal all --enable-tests
cabal test --builddir=Build/cabal all --test-show-details=direct
cargo test -p tactus-runtime --locked
```

The repository tests use fake plugins and do not make model requests.

## 2. Initialize beside the old workspace

Prefer a clean project copy or a new branch so rollback is just a switch back
to the untouched `0.2` checkout. Point Tactus at this repository's Clef Cabal
package:

```powershell
tactus init D:\path\to\project-0.3 --sdk D:\path\to\Agenstro\clef-sdk
tactus doctor --root D:\path\to\project-0.3
tactus list --root D:\path\to\project-0.3
```

On Ubuntu, use the equivalent absolute POSIX paths. `init` creates only missing
files under `.tactus` and preserves existing files. It deliberately does not
rewrite an old `.tactus` directory, so inspect or move a backed-up `0.2`
directory before initializing the new project copy.

## 3. Re-express workflows as Haskell

Create ordered entry files such as `.tactus/scripts/010_plan.hs`. Convert each
typed provider step to a `Task`, external observation/action to an `Operation`,
and data dependency to ordinary Haskell values and `do` notation. Use
`parallel` only where both branches may run concurrently.

There is intentionally no one-to-one mapping for daemon scheduling, artifact
publication, checkpoint restore, notebook cells, or arbitrary Python state. A
recurring workflow can now be re-authored as a typed Haskell Segno
`PersistentTask`, but its trigger cursor, business state, and lifecycle start
fresh; no command imports a `0.2` Segno package or database.

## 4. Review plugin configuration

The generated `.tactus/tactus.toml` defines `codex`, `claude-code`, and
`opencode` providers and the `workspace.paths` effect. Commands are argv arrays
and inherit the launching environment. Keep credentials in the provider's
normal environment/configuration; do not copy secrets into workflow source or
runtime JSON.

OpenCode deserves an explicit acceptance decision. Its adapter requests
`--auto` and injects `permission=allow`, but explicit deny and managed policy
may still prevent operations. Tactus therefore reports that full bypass is not
guaranteed.

## 5. Validate without a model call

Run the non-live checks first:

```powershell
tactus prompt --root D:\path\to\project-0.3
tactus check --root D:\path\to\project-0.3
tactus doctor --root D:\path\to\project-0.3
tactus smoke --root D:\path\to\project-0.3
```

The default `smoke` request checks local executable versions and sets
`live=false`; it does not send a provider prompt. It still requires the
configured provider executables to be installed. `generate`, `smoke --live`,
and a provider-using program started by `run` can make real model calls, so use
them only after reviewing commands, credentials, workspace scope, and cost.

## 6. Cut over and roll back

Cut over only after every selected script passes `tactus check`, required
plugins pass the appropriate smoke level, and any live acceptance test is
intentional. Motivo `0.3` may visualize the new workspace, but it cannot open
or migrate old daemon/cell state. Haskell Segno `0.3` can initialize the new
workspace after Tactus, but it likewise does not consume old scheduler state.

If acceptance fails, stop the `0.3` commands and return to the untouched `0.2`
checkout and its matching environment/state copy. No `0.3` command migrates or
deletes `0.2` state, so a side-by-side cutover is the supported rollback
strategy for this alpha.
